# QuestMind 投资人 BP 草案

版本：2026-09-08 v2｜用途：天使轮沟通底稿

> 本文以当前代码为事实基础，区分“已实现”“待真实环境验收”和“规划中”。用户规模、收入、留存和市场规模没有在代码中出现，正式路演前必须替换为真实数据。

## 1. 一句话介绍

QuestMind 是一个以 AI 角色 Alice 为入口、以个人目标为主线、以用户资料为知识来源、以持续反馈为驱动的陪伴式学习与个人成长平台。它把“我想完成一件事”转化为“今天做什么、我掌握了多少、下一步怎么复习”，并在执行过程中提供长期的情绪陪伴。

## 2. 投资摘要

用户面对的核心问题不是缺少一个待办清单，而是目标太大、计划难以执行、资料难以消化、独自学习容易中断。通用 AI 能回答问题，却通常不理解用户的目标进度、私有资料和长期状态。

QuestMind 用一条连续链路解决这个问题：

```text
目标输入 → 状态诊断 → 个性化计划 → 每日执行
→ 资料理解 → Alice讲解 → 测验验证 → 掌握度更新
→ 间隔复习 → 关系陪伴与复盘
```

当前代码已形成 Web、桌面和 Android 共用的产品骨架，包含 Goals、LectureRoom、Room、课程理解引擎、Alice 关系记忆、语音和桌宠入口。下一阶段重点是选定一个高频垂直场景，验证留存、学习效果、AI成本和付费转化。

## 3. 用户痛点

| 用户问题 | 现有工具的缺口 | QuestMind的处理方式 |
| --- | --- | --- |
| 想学的目标太大 | 待办工具只记录，不帮用户落地 | AI追问现状并生成子目标和每日任务 |
| 教材、课件、试卷分散 | 通用聊天需要用户反复粘贴内容 | 上传资料后分类、提取知识点并保留证据 |
| 学过但不知道是否掌握 | 内容平台重消费，反馈弱 | 测验、掌握度事件、错误标签和复习队列 |
| 计划会因新资料或进度变化失效 | 一次性计划无法持续更新 | 新资料和学习事件触发计划修订与回滚 |
| 一个人学习容易放弃 | 效率工具缺少情绪支持 | Alice在关系空间和行动空间持续陪伴 |

## 4. 产品与核心闭环

### 4.1 Goals：把目标变成今天的行动

用户可以手动创建目标，也可以进入 AI 智能创建向导。向导会读取目标、当前状态、时间和参考资料，生成子目标、每日任务、难度、清单和资料引用。目标支持优先级、起止日期、暂停、完成和进度计算。

### 4.2 课程理解引擎：把资料变成可学习的结构

系统支持 PDF、DOCX、TXT/Markdown 和图片附件。课程引擎将资料分类为教材、课件、笔记、考试范围、作业、习题、试卷等，抽取标题、公式、例题、练习、警告、总结和推导，再构建知识节点、先修关系、多源证据、重要度和掌握度。

### 4.3 LectureRoom：在资料上下文中学习

讲义学习室提供 PDF 页面渲染、Word 文本查看和 Alice 学习桌宠。用户可以选择课程概览、章节讲解、重点提炼、举例和测验准备，也可以继续追问“没听懂”“换个例子”等问题。

### 4.4 反馈与复习：让计划随行为变化

用户的自评、答对、答错、提示和任务完成都会成为学习事件。系统按 1、3、7、14、30 天安排复习，支持今日复习队列、薄弱点优先和可用时长筛选。上传新资料时，课程模型可以增量更新并保留计划版本。

### 4.5 Alice：提升留存的角色资产

Alice 在小屋中承担日常陪伴、情绪支持和复盘，在目标页承担学习指导、讲解、提问和任务推进。关系记忆按 global、cabin、goal、study/project 等范围隔离，并记录关键时刻和待跟进事项。语音、情绪立绘、日记、兴趣分享和桌面宠物是后续增强长期使用关系的产品资产。

## 6. 目标用户与切入市场

首阶段建议聚焦“高频、结果明确、愿意付费”的学习场景：考研、考公、四六级、职业资格考试、编程和语言自学。核心用户是 16–35 岁的学生、自学者与职场人，他们有明确目标、个人资料和持续监督需求。

中长期可扩展到健身、阅读、职业成长和企业学习，但这些方向需要独立的内容模板、专业评估和渠道验证。

## 7. 竞争定位

QuestMind 位于三类产品的交叉位置：效率工具负责目标与任务，AI学习工具负责资料讲解与练习，AI陪伴产品负责关系、语音与情绪支持。

差异化来自五个组合：

1. 从目标到每日行动的执行闭环。
2. 从个人资料到知识节点和证据的课程理解。
3. 以掌握度事件驱动计划持续修订。
4. Alice 的角色人格、关系记忆和场景隔离。
5. Web、桌面、Android 和未来硬件共享同一产品基础。

## 8. 商业模式

采用“免费入口 + Pro订阅 + 内容与角色增值 + 硬件 + B端授权”的组合，先用个人用户验证留存和付费，再扩展机构客户。

| 层级 | 产品内容 | 收入逻辑 |
| --- | --- | --- |
| 免费版 | 基础目标、有限对话、基础测验和专注记录 | 降低首次使用门槛 |
| Pro会员 | 更高 AI 配额、更多资料、更长上下文、高级学习模式、完整语音和记忆 | 月付/年付订阅 |
| 内容增值 | 考试冲刺包、语言/编程场景包、专业课程模板 | 单次购买或会员权益 |
| 角色增值 | 声线、服装、立绘、房间主题、剧情内容 | 数字商品 |
| 硬件 | Alice桌宠、陪伴手办、屏幕或投影设备 | 设备毛利与软件订阅联动 |
| B端 | 学校、培训机构、企业学习空间 | 席位/项目授权 |

## 9. 增长路径

```text
免费目标模板/考试模板
→ AI自动生成计划
→ 上传个人教材与试卷
→ 获得资料驱动的讲解和测验
→ 形成复习习惯与Alice关系
→ Pro订阅
→ 用户分享目标模板、学习成果和角色内容
```

优先渠道包括考试社群、校园大使、学习博主、教师与培训机构合作。增长实验应围绕一个垂直场景展开，避免早期同时覆盖所有个人成长类别。

## 10. 产品与技术壁垒

- 课程引擎把资料分类、教学块、知识节点、证据、重要度和掌握度连接起来。
- 连续计划引擎能响应新资料、学习事件和截止日期变化，并支持版本回滚。
- 结构化学习上下文限制模型输入范围，减少整份资料反复拼接带来的成本和噪声。
- Alice 的场景隔离和关系记忆让同一角色既能陪伴生活，也能进入目标行动空间。
- 本地优先、云端同步和跨端交付为桌面宠物与未来硬件提供基础。

## 15. 路演结尾

QuestMind 正在把学习产品从“记录任务”推进到“理解目标、理解资料、理解状态并陪用户完成”。融资后的首要任务不是堆叠功能，而是用一个高频场景证明：用户会持续回来完成目标，资料驱动的学习反馈能带来更好的结果，Alice 的陪伴能把一次使用变成长期关系。

## 17. TAM / SAM / SOM 的计算方法

正式融资版建议采用“自下而上”的市场模型：

```text
TAM = 可服务学习人群 × 年均可接受支出
SAM = 首阶段覆盖场景人数 × 产品适配率 × 年均订阅价格
SOM = 未来3年可触达用户 × 注册转化率 × 付费转化率 × 年均客单价
```

建议先从以下变量收集真实数据：

| 变量 | 数据来源 | 当前状态 |
| --- | --- | --- |
| 单个考试/课程场景的活跃备考人数 | 教育部门、考试机构、渠道调研 | 待收集 |
| 用户对AI学习会员的价格接受区间 | 付费问卷与真实支付页测试 | 待验证 |
| 内容渠道到注册的转化率 | 落地页与邀请码 | 待验证 |
| 注册到首个目标创建率 | 产品埋点 | 待验证 |
| 首个目标到7日留存率 | 产品埋点 | 待验证 |
| 免费到Pro的转化率 | 真实订阅实验 | 待验证 |

## 18. 定价与单位经济模型

以下仅作为测试假设，不代表已经确定的售价：

| 方案 | 建议测试价格 | 核心权益 | 验证目标 |
| --- | ---: | --- | --- |
| 月度Pro | ¥29–49/月 | 更多资料、AI额度、高级学习模式 | 找到低决策门槛价格 |
| 年度Pro | ¥199–299/年 | 月度Pro权益与年度优惠 | 验证长期承诺意愿 |
| 考试冲刺包 | ¥39–99/套 | 场景模板、复习结构与专属提示词 | 验证内容增值 |
| 角色增值包 | ¥9–39/项 | 声线、服装、立绘或房间主题 | 验证IP付费 |

单位经济应按以下公式持续跟踪：

```text
月度单用户毛利
= 订阅收入 + 增值收入
- 模型调用成本 - 语音成本 - 存储与带宽 - 渠道分成 - 支付手续费

LTV = 月度单用户毛利 × 平均付费月数
回收周期 = CAC ÷ 月度单用户毛利
```

早期不建议依赖广告收入。QuestMind需要用户上传个人资料并建立长期关系，广告会降低信任和学习沉浸感。

## 19. 产品护城河形成路径

QuestMind 的壁垒不会仅来自调用某一个模型，而会来自逐步积累的产品状态和反馈数据：

1. 目标数据：用户长期目标、期限、计划版本和完成行为。
2. 学习数据：知识节点、来源证据、掌握度、错误标签和复习结果。
3. 关系数据：偏好、关键时刻、待跟进事项和场景化互动反馈。
4. 产品IP：Alice 的形象、人格、声音、剧情和桌面陪伴入口。
5. 工作流：从目标输入到计划修订的连续系统，而不是一次性生成内容。

随着用户使用时间增长，系统对“这个用户下一步最应该做什么”的判断会更准确，迁移成本也会自然提高。产品必须同时提供记忆查看、删除和导出能力，避免用不透明的数据锁定用户。

## 20. 冷启动实验设计

建议用一个明确考试场景完成首轮验证。以下以“大学期末/资格考试”为例：

### 实验A：计划价值

- 入口：用户填写考试日期、每天可用时间和薄弱章节。
- 产品动作：生成7–30天计划与当日第一项任务。
- 核心指标：计划生成完成率、首项任务启动率、首日完成率。

### 实验B：资料价值

- 入口：鼓励上传课程讲义、错题或考试范围。
- 产品动作：生成知识主线、重点、练习和引用证据。
- 核心指标：资料上传率、讲解使用率、同一资料7日内复用次数。

### 实验C：Alice留存价值

- 入口：完成任务后由Alice提供反馈，并在下一次打开时跟进。
- 产品动作：测试有/无关系记忆的两组体验。
- 核心指标：次日回访率、7日学习天数、主动对话次数、关闭陪伴比例。

### 实验D：付费价值

- 入口：免费额度接近上限时展示Pro方案。
- 产品动作：测试资料数量、高级复习和语音权益的不同组合。
- 核心指标：支付页到达率、购买率、退款率和付费后30日留存。

| 用户 | 新增注册、MAU、付费用户、留存、流失 |
| 收入 | 月付、年付、内容包、角色增值、机构收入 |

| 团队 | 研发、产品、设计、增长、内容和运营薪酬 |
| 获客 | 内容制作、投放、校园渠道、合作分成 |
| 硬件 | 原型、模具、认证、备货、售后和坏品率 |
| 现金 | 月度净现金流、期末余额、可用月数和下一轮融资节点 |

建议将硬件财务模型与软件订阅模型分开，只有在预售意愿、BOM、返修率和供应链交期得到验证后，才将硬件收入并入基准预测。

## 23. 数据、安全与合规路线

QuestMind会处理学习资料、对话、关系记忆和可能涉及未成年人的数据。融资后的工程化工作应包括：

- 完成所有 Supabase 迁移、RLS 和真实账号端到端验收。
- 建立资料与记忆的查看、导出、单项删除和全部清除机制。
- 明确模型供应商是否用于训练、数据保留时间和跨境处理方式。
- 为未成年人增加年龄分层、内容限制、家长与学校适用政策。
- 对测验、学习建议和AI生成计划保留可解释来源及错误反馈入口。
- 建立模型成本、延迟、失败率、敏感内容和数据访问审计。

## 25. 投资人常见问题

### 为什么用户不用通用AI？

通用AI擅长回答当下问题。QuestMind把目标状态、个人资料、任务完成、测验结果、复习队列和Alice关系放在同一个持续系统中，减少用户重复组织上下文的成本。

### 为什么需要Alice？

Alice提供稳定的交互入口，把任务反馈、复习提醒和日常复盘连接成长期关系。是否能提高留存仍需通过对照实验验证。

### 课程引擎是否依赖单一模型？

当前AI服务可通过客户端和Edge Function调用模型。课程分类、知识结构、掌握度和复习调度具有独立服务层，未来可以接入多模型路由。

### 为什么现在考虑硬件？

桌宠和实体设备能让陪伴从应用内延伸到日常环境。硬件应先做原型和预售验证，不应在软件留存和供应链指标不清晰时直接量产。

### 项目当前最大的风险是什么？

最大的风险不是缺功能，而是尚未证明一个垂直场景中用户会持续使用并付费。下一阶段应围绕真实留存、学习效果和单位经济集中验证。

## 27. 90秒路演开场稿

QuestMind希望解决一个很具体的问题：很多人有明确的学习目标，也拥有教材、课件和试卷，但他们不知道今天应该先做什么，也很难一个人坚持到结果。

用户在QuestMind输入目标，Alice会先了解他的现状和时间，再生成子目标与每日任务。用户上传自己的资料后，系统会识别知识点、重点和先修关系，在讲义学习室里提供讲解与测验。每一次答对、答错和任务完成都会更新掌握度、复习队列和后续计划。

我们已经完成Web、桌面和Android共用的产品原型，并建立课程理解、连续计划和Alice关系记忆的核心代码。下一阶段，我们将聚焦一个高频考试或自学场景，验证7日与30日留存、学习效果、AI成本和Pro订阅转化。本轮建议融资200–500万元，用18个月完成产品闭环和商业验证。
